# 🐰 兔兔下载器（Tutu Downloader）

一个桌面小工具：把**小红书 / 微博 / 抖音**作者主页里的图片、视频、Live 实况图，批量下载到本地。

- 三个平台各自独立成页，互不干扰
- Live 实况图导出为 **MP4 视频，原画直取 / 无损封装，不重新编码**
- macOS 风格界面，操作只有三步：**粘贴作者主页链接 → 勾选作品 → 点下载**

---

## 一、三步就能用

1. **粘贴链接**：在平台网页里打开某个作者的主页，复制地址栏的链接，粘到输入框（也可以直接点输入框右侧的「粘贴」）。
2. **勾选作品**：点「开始解析」，等左边出现作品卡片后，点卡片**右上角的圆圈**勾选（或用「全选」）。想先看看某条作品长什么样，直接点卡片空白处，右侧会跳到那条作品。
3. **点下载**：点右下角「下载选中」，进度会显示在「传输」标签里。下载完成后会弹出完成提示，**不会再自动打开保存目录**（要自己看文件，点右上角「📁 下载目录」）。

> 第一次使用请先登录：右边那块就是平台真实网页，扫码或账号登录一次，登录状态会一直保留（每个平台独立保存，互不影响）。

保存位置、同时下载数量、自动加载页数（默认 40 屏）、实况图是否导出为 MP4，都可以在右上角齿轮里改。

### 界面速览

| 位置 | 是什么 |

| 左侧作品卡片 · **卡片空白处** | **点卡片就在右侧打开这条作品**，卡片会描一圈高亮边，标题栏变成「预览：作品名」 |
| 左侧作品卡片 · **右上角圆圈** | 只负责勾选 / 取消勾选，不会跳页面。勾完点右下角「下载选中」 |

| 左侧作品卡片 · **类型徽标** | `图片` / `视频` / `实况`（红色）。「实况」是解析阶段逐条比对作品详情认出来的，不是列表接口给的 |

## 二、怎么运行

### 方式 A：免安装，双击就能用（最省事）

双击 `dist/兔兔下载器-1.0.4-免安装版.exe`。

- 单个 exe，**不需要安装、不会写入注册表**，放 U 盘里换台电脑也能跑
- 第一次启动会自解压到临时目录，稍等几秒；之后再启动会快很多
- 设置与登录状态保存在 `%APPDATA%\兔兔下载器`，卸载/删掉 exe 都不会丢

### 方式 B：安装版（会创建桌面和开始菜单快捷方式）

双击 `dist/兔兔下载器-1.0.4-安装包.exe`，按提示安装即可。

### 方式 C：源码运行（开发 / 想改代码）

```bash
cd tutu-downloader
npm install          # 首次需要；Electron 较大，国内可加 --registry=https://registry.npmmirror.com
npm start
```

- 需要 Node.js 18+（本机实测 Node 22 正常）
- 首次 `npm install` 之后不要再随便删 `node_modules/@ffmpeg-installer`，实况图转换靠它

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm start` | 启动应用 |
| `npm test` | 跑 48 项单元测试（解析规则、下载重试、实况转换） |
| `npm run e2e` | 离线端到端联调：模拟一批作品，真下载、真转换、真落盘，20 项断言 |

| `npm run nettest` | 打开抖音首页，打印能抓到的接口（排查用） |

| `npm run dist:portable` | 只出免安装版 |
| `npm run icons` | 用 `build/raw/` 里的原图重新生成全套图标 |

### 想自己复核一遍（可选）

## 三、为什么这么做（设计说明）

### 1. 解析：不自己造签名，让平台自己发请求

三个平台的作品列表接口都带风控签名（小红书的 `X-s`、抖音的 `a_bogus`、微博的 `XSRF` 等），自己拼 HTTP 请求几乎一定会被拦。

所以这里换了个思路：

```
内嵌真实网页（每个平台一个独立 session 分区）
        ↓  页面自己发请求（签名天然合法、Cookie 天然带上）
DevTools 协议监听响应 → 读出 JSON → 按平台规则提取作品
        ↓  如果接口结构变了，还有「深度扫描兜底」把媒体地址捞出来
下载：用同一个 session 发请求（带 Cookie / Referer），断点续传 + 重试
```

好处是：不用逆向签名算法，平台改版时也不至于立刻失效；代价是需要内嵌页面，解析时会自动滚动加载（可在设置里限制页数）。

**微博走的是另一条更稳的路**：它的 `/ajax/statuses/mymblog` 只校验 Cookie、不校验签名，于是直接让页面自己 `fetch` 并翻页，拿到的是和网页完全一样的 JSON。这比「等页面自己发请求再嗅探」稳定得多，也不受首屏懒加载影响（微博新版主页的 DOM 里连作品卡片的 `[mid]` 都没有了）。

### 1.1 下载：Referer 必须显式写在请求头里

三个平台的 CDN 都校验 Referer，缺了就是 403。这里踩过一个坑：

```
会话层 webRequest.onBeforeSendHeaders 注入 Referer   →  主进程 fetch 实际没带上 → 403
请求头里直接写 Referer                              →  200（字节数一致）
```

所以下载时由 `downloader.js` 把平台 Referer 显式塞进请求头（`platform.referer`），而不是依赖会话层注入。另外留了一条兜底：图片被 CDN 拒绝时，改由平台页面自己 `fetch` 一次、base64 回传（限 12 MB），避免偶发风控把整条作品判失败。

### 2. 实况图：只搬运，不重编码

- 平台能给出实况视频的原始流 → **直接下载原始 MP4**，字节级原画
- 原始流是 `.mov` 等容器 → `ffmpeg -c copy` 只换壳（不解码、不重编码），分辨率与码率不变
- 换壳后会用 ffmpeg 读一遍新文件的编码/分辨率/时长做校验，**校验不通过就退回原始文件**，宁可不换壳也不降质
- 没有 ffmpeg 时：保留原始文件，绝不偷偷转码

### 3. 画质相关的小细节

- 小红书 `sns-img` 的缩放参数（`imageView2/...`）会被去掉，取原图
- 微博 `mw690/`、`thumb150/` 这类缩略路径会换成 `large/`
- 抖音 `~tplv-...` 样式模板后缀会去掉，但**签名查询串必须保留**，否则 403
- 抖音视频优先选 `bit_rate` 里分辨率/码率最高的那条，并把 `playwm` 换成 `play`（去水印）

## 五、常见问题

**解析不到作品 / 提示未登录**
先在右侧页面完成登录（小红书扫码、微博账号、抖音扫码），登录后再点一次「开始解析」。部分账号主页需要登录才可见。

**链接报错「不是作者主页链接」**
要复制**作者主页**地址（例如 `xiaohongshu.com/user/profile/xxx`、`weibo.com/u/1234567890`、`douyin.com/user/MS4w...`），不是单条作品链接。从微信 / QQ 里复制出来的短链也能用，程序会自动展开。

**某个作品下载失败**
任务卡片会显示具体原因（无权限 / 文件不存在 / 网络中断）。点左下角「重试失败项」只重跑失败的那几个，已成功的不会重复下载。

**下载下来打不开 / 是 0 字节**
一般是没有权限（链接过期或需登录）。程序会自动重试 3 次，仍失败会标记为失败并保留原因，不会留下残缺文件（临时文件统一用 `.part` 后缀，成功后才改名）。

**实况图为什么是 mp4 而不是「会动的照片」**
Live Photo 本质是「一张图 + 一段短视频」。导出为 MP4 后，任何播放器都能播放，画质与分辨率保持原始。原始静态封面也会保留（多文件作品里序号靠前的就是它）。

## 六、已知限制

1. **必须登录**：三个平台的作品列表接口在未登录状态下大多返回空，程序会在提示里告诉你先登录。
2. **平台改版风险**：解析规则按当前接口结构编写，并用「深度扫描」兜底；如果平台大改结构，可能需要更新 `src/main/platforms/*.js`。
3. **解析速度**：为了触发签名请求，解析时会自动滚动加载，20 个作品大约 10–20 秒，可在设置里调「自动加载页数」（默认 40 屏，够覆盖几百条作品）。

4. **实况图要靠详情数据才能认出来**：列表接口只给静图（小红书的 `user_posted` 连 `image_list` 都没有），动态那半段只在详情数据里——微博在 `/ajax/statuses/show` 的 `pic_infos[].video`，小红书在笔记页 `__INITIAL_STATE__` 的 `imageList[].stream`。所以解析阶段会逐条取详情把 Live 图认出来（卡片上标「实况」），这一步必然比只读列表慢一点。设置里的「实况图导出为 MP4」只决定**导不导出**视频，不影响识别。
5. **小红书会混淆视频流的字段名**：访问过作者主页之后，平台会把 `stream` 里的编码键名从 `h264/h265/av1` 换成 `EF4/EF5/EF6/EF7` 之类（每次都不一样）。程序不认死键名，而是把容器里所有数组值都当候选流，再按分辨率/码率挑最好的，所以混淆不影响识别。
6. **抖音图集很多本身就是「实况图集」**：一条图集里每张图都可能自带一段小视频，程序会按实况处理（每张静图配一个 mp4）。抖音图片地址带 `~tplv-…` 模板后缀，**这个后缀参与 CDN 签名、不能删**（删了就是 403），画质是在平台给的无水印 / jpeg 变体里挑最好的那档。
7. **页面是懒渲染的**：右侧平台页一屏大约只渲染 30 个卡片，左边的作品总数会比「一眼能看到的卡片」多；把右侧往下滚，多出来的那些会按同样顺序出现，位置和左侧一致。
8. **仅个人备份用途**：下载内容请遵守各平台用户协议与著作权规定，不要二次传播他人作品。
